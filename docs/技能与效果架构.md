# 技能与效果架构（定案）

> 状态：✅ 定案（2026-09-09，用户拍板选 (A) 最小核心：状态系统 + 修饰器扩展点）。
> 本文件是**效果/状态机制的唯一依据**；任务书见 `docs/tasks/P3_8-效果系统.md`。
> 前提约束：引擎保持纯逻辑零 I/O；确定性随机可复现（管线顺序冻结）；行为迁移必须零漂移。

## 一、为什么是"组件化"而不是"继承"

技能不是**种类树**，而是**机制的笛卡尔积**（伤害×范围×状态×代价）。继承式
（`穿甲弹(Bullet)`）在机制组合时会产生类爆炸与重复代码；我们的技能数量多、组合复杂，
因此采用：**效果是对象，由固定系统处理**（B 的架构内核）+ **效果内部用修饰器组合**
（A 的数据形态）。

**穿甲弹的正确建模**：`基础伤害效果 + armor_pen 修饰器 + extra_dmg 修饰器`
——穿透是独立修饰器，作用在"防御项"上，与基础伤害解耦（是否附带额外伤害由数据决定，非通则）。

## 二、明确不做（红线；写出来即设计过重）

- ❌ 通用 ECS / 实体查询 / 组件注册中心
- ❌ 事件总线 / 消息系统（回合制固定管线足够）
- ❌ 效果脚本 DSL / 热插拔
- ❌ 每个效果一个类（用数据模板 + 注册函数）
- ❌ 连续空间/物理（移动、碰撞体积、投射物飞行）——我们是回合制离散时间
- ❌ 提前实现召唤物/地形/链式目标等尚无需求的机制

**规模预算**：`engine/effects.py` ≤ 220 行、`content/effects.py` ≤ 100 行。超预算即回退设计。

## 三、数据模型

```python
# content/effects.py —— 效果模板（纯数据）
@dataclass(frozen=True)
class EffectTemplate:
    key: str                 # 稳定键（数据引用，禁中文名）
    name: str                # 展示名（"定身"/"破势"…）
    tags: tuple = ()         # ("control",)/("buff",)/("debuff",)
    duration: int = 1        # 回合数；0 = 立即生效、不入效果袋
    max_stacks: int = 1
    stack_rule: str = "refresh"   # refresh / stack / ignore
    apply_key: str = ""      # 立即结算函数键（duration=0 必填）
    tick_key: str = ""       # 每回合结算函数键（duration>0 可选）
    params: dict = {}        # 模板默认参数（如 {"mult": 0.5}）
    desc: str = ""
```

```python
# engine/effects.py —— 运行时对象（可序列化）
@dataclass
class EffectInstance:
    key: str; source: str = "player"; stacks: int = 1
    duration: int = 1; params: dict = {}
    # to_dict()/from_dict()：战报与测试用（战斗运行时不入存档）

class EffectBag:            # 挂在每个参战者身上
    apply(key, source, rng, ctx) -> EffectInstance | None   # 按 stack_rule 处理
    has(key) / get(key) / remove(key) / clear()
    tick() -> list[str]     # duration-1，到期移除并返回到期键
    to_list() -> list[dict]
```

**叠层规则**：`refresh`=重置持续、层数保持 1；`stack`=层数 +1（封顶 max_stacks）并重置持续；
`ignore`=已存在则不重复施加。

## 四、结算管线（顺序冻结，随机流才可复现）

```
每回合：
1) 回合初：玩家灵气自动回复（同现状）
2) 玩家动作：
   attack / skill(attack) → resolve_damage(DamageCtx) 造成伤害；skill 若带 effect_key 则同时施加
   skill(defense)         → 施加 guard 效果
   skill(utility)         → 施加 skill.effect_key（instant 立即结算 / status 入袋）
   defend                 → 施加 guard
   gather / flee          → 同现状
3) 敌方行动：
   若敌方有 root          → 跳过行动（文案同现状）
   否则若玩家有 evade     → rng.chance(evade.chance) 落空
   否则 基础敌伤 resolve_damage(...)
        敌方 weaken → dmg = max(1, round(dmg × mult))
        玩家 guard  → dmg = max(1, round(dmg × mult))     ← 顺序与现状一致
        结算玩家 HP
4) 回合末：双方 EffectBag.tick()（duration-1、到期移除）
5) 战报：文本（同现状）+ 结构化 data（含双方效果列表）
```

**伤害结算**（无修饰器时与现状公式逐位一致）：

```python
def resolve_damage(ctx) -> int:
    v = ctx.base + ctx.attack * ctx.attack_ratio - ctx.defense * ctx.defense_ratio
    for key in MODIFIER_ORDER:              # ("armor_pen", "extra_dmg", ...)
        if key in ctx.modifiers:
            v = MODIFIERS[key](ctx, v, ctx.modifiers[key])
    v *= ctx.element_mult                   # 五行乘区（P2 克环；P5 威力层接这里）
    v *= ctx.jitter                         # ±10%（复用同一随机流）
    return max(1, round(v))
```

内置修饰器：
- `armor_pen`：`v += ctx.defense × ctx.defense_ratio × params`（params∈[0,1] 穿透比例）
- `extra_dmg`：`v += params`（固定加伤）

扩展点：`register_effect(template)`、`register_modifier(key, fn)`（追加到顺序末尾）。
**新增内容 = 加数据，不改结算代码。**

## 五、现有内容迁移映射（行为零漂移）

| 现状 | 迁移后 |
|---|---|
| `battle.guard`（bool） | `guard` 效果（duration 1，params {"mult": 0.5}） |
| `battle.enemy_rooted` | 敌方袋中 `root` 效果 |
| `battle.enemy_weakened` | 敌方袋中 `weaken` 效果（mult 0.5） |
| `battle.self_evading` | 玩家袋中 `evade` 效果（chance 0.5） |
| `Skill.utility_effect` | `Skill.effect_key`（模板键；`utility_effect` 作输出别名保留） |
| 攻击/敌攻硬编码公式 | `resolve_damage(DamageCtx)`（参数与现状一致） |
| `Battle.guard/enemy_rooted/...` | 只读 property（派生自效果袋，标注 deprecated） |

**兼容性**：`Battle.do()` 三元组返回、`last_reason`、`used`、`available_skills()`、`ke()`、
`view()`、`p_*`/`e_*` 属性全部不变；`UTIL_EFFECT_LABELS` 由模板 name 生成。
