# 实现路线图（从当前可玩状态 → 完整游戏）

> 本文档是**实现顺序**的唯一依据，与 `设计定案.md`（规则）、`数据格式草案.md`（数据格式）配套。
> 每阶段结束都必须**可玩、可测**（`tests/smoke.py` 能跑、CLI 能玩），再做下一阶段。
> 排序原则：依赖优先 + 每步可玩增量最大 + 用户指定优先级（功法→用户已说"不急"，故后置并拆浅深两层）。
> 各阶段由 subagent 执行，**未开始**阶段的任务书写在 `docs/tasks/` 下按 `P<n>-<名>.md` 命名，
> 含必读清单/规格/验收判据；完成验收后归档到 `docs/archive/tasks/`。

## P10：数值标定 + 平衡（贯穿性收尾）

> **指标哲学（2026-09-09 用户质疑后修正）**：smoke bot 的通关率**不是平衡指标**，它是
> "固定种子 + 固定策略"的**回归指纹**（值变了要先问"是不是引擎行为变了"，而不是"该调数值了"）。
> 单策略 bot 的胜率主要由 bot 策略决定，与游戏是否好玩无关；内容组合爆炸后更不可能靠它"测平衡"。
> 真正可度量的平衡指标（P10 才做）：多策略 bot（保守/激进/专精）采样后的 **支配策略检测**
> （某一路线胜率显著高于其他）、**资源曲线**（灵石/丹药/境界的中位到达时间）、**寿元压力分布**、
> 关键选择的**收益方差**。阈值不预设，由采样数据 + 用户手感共同确定。
>
> **已铺好的地基（2026-09-10）**：`tools/replay.py` 提供固定种子/脚本的**指纹**与 `--compare`
> A/B 对照（bot / script 两模式），取代此前手搓的 `git worktree` 脚本；P10 的多策略采样
> 可在其 `bot` 模式上加"策略"维度，指纹字段（境界/资源曲线/rng 游标）直接复用。
- [ ] 用 smoke bot 大规模跑局（千局）统计：各境界到达率、道陨分布、经济曲线
- [ ] 多策略 bot（≥3 种策略）对比，检测支配策略与收益方差；灵根/出身有区分度
- [ ] 内容组合可测性：效果/规则走数据+注册表，单测覆盖"规则×修饰器"抽样矩阵（pairwise/正交表），
      而非全组合枚举；新增内容只补契约测试，不重跑全量

- 完成判据：数据说话，非手感拍脑袋；且**不设"目标通关率"**（那会把平衡变成迎合 bot 策略）
