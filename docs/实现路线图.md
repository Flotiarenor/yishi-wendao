# 实现路线图（从当前可玩状态 → 完整游戏）

> 本文档是**实现顺序**的唯一依据，与 `设计定案.md`（规则）、`数据格式草案.md`（数据格式）配套。
> 每阶段结束都必须**可玩、可测**（`tests/smoke.py` 能跑、CLI 能玩），再做下一阶段。
> 排序原则：依赖优先 + 每步可玩增量最大 + 用户指定优先级（功法→用户已说"不急"，故后置并拆浅深两层）。
> 各阶段由**主会话直接实现**（2026-09-10 起不再使用 subagent），**未开始**阶段的任务书写在 `docs/tasks/`
> 下按 `P<n>-<名>.md` 命名（规格 + 验收判据，供记录与复核）；完成验收后归档到 `docs/archive/tasks/`。
>
> ⚠️ **口径（2026-09-10 统一）**：**"现在是什么样"只以根 `README.md`「当前状态」事实表为准**。
> 本文件各阶段条目里的测试项数、smoke 指纹、格宽、视野、性能数字都是**当时的验收记录**，
> **不再维护、不作现状依据**——它们的价值在于"当时为什么这样做、验收了什么"。
> 新增条目**不要再复制当前数字**，写「见根 README 事实表」。

## P12：数值标定 + 平衡（贯穿性收尾）

> **指标哲学（2026-09-09 用户质疑后修正）**：smoke bot 的通关率**不是平衡指标**，它是
> "固定种子 + 固定策略"的**回归指纹**（值变了要先问"是不是引擎行为变了"，而不是"该调数值了"）。
> 单策略 bot 的胜率主要由 bot 策略决定，与游戏是否好玩无关；内容组合爆炸后更不可能靠它"测平衡"。
> 真正可度量的平衡指标（P12 才做）：多策略 bot（保守/激进/专精）采样后的 **支配策略检测**
> （某一路线胜率显著高于其他）、**资源曲线**（灵石/丹药/境界的中位到达时间）、**寿元压力分布**、
> 关键选择的**收益方差**。阈值不预设，由采样数据 + 用户手感共同确定。
>
> **已铺好的地基（2026-09-10）**：`tools/replay.py` 提供固定种子/脚本的**指纹**与 `--compare`
