## 零、为什么现在做（T3 的真实工作量）

`engine/worldmap.py` 的算法层**已经完成**（窗口化 A\* + octile 可采纳启发 + 防穿角，
独立 Dijkstra 对照最优）。**T3 不重做寻路**，要做的是三件"接进游戏"的事：

1. **时间接真**：`engine/game.py:661` 仍是 `self._advance_days(S.TRAVEL_DAYS)`——**固定 3 日**，
   与地形、距离、境界全无关系。定案 §4.1 要求"时间 = 路径积分 ∫ds/速度"。
2. **候选路径**：定案 §4.2 要求给 2–3 条候选（最快 / 最安全 / 最隐蔽）+ 过滤器。
3. **手动探路 + 存档**：无舆图时直线推进遇阻停下；玩家位置从"地点字符串"迁到 `WorldState.pos`。

### 0.1 实测发现的必须先修的问题（本任务书动因）

对 4 组起终点跑三档 `profile`（seed 20260910，城镇对）：

| 起终点 | fastest | safe | stealth |
|---|---|---|---|
| 441 里 | 13.4 日 | **13.4 日（完全相同）** | 22.8 日 |
| 4 669 里 | 807 日 | **2 228 日**（绕远 2.8×，危险地形占比 **86% → 86%**） | 813 日 |
| 13 826 里 | 509 日（官道 67%） | **513 日（几乎相同）** | 820 日（官道 22%） |
| 23 790 里 | 823 日 | **827 日（几乎相同）** | **1 279 日（+55%）** |

**结论：三档候选在当前代价模型下是假的**——`safe` 兑现不了"更安全"（危险权重从 3.0 扫到 100，
危险地形占比反而 **86% → 99%**、耗时翻 70 倍），`stealth` 在长距离过罚（+55% 时间，玩家不会选）。
**若不修代价模型，T3 就是"给玩家三个按钮、其中两个是坑"**（用户已拍板：**先修**）。

**根因**：危险惩罚做在**速度域乘法**（`mult = 1 + 3×danger` → `cost = w/sp×mult`），
而每格又取 9 点采样的**最小代价**——两者叠加把危险惩罚结构性抹平了。

### 0.2 修完之后的新发现（2026-09-10 实施期，**重要**）

代价域线性组合**已实现并标定**（参数见 `engine/worldmap.py` 的 `PROFILES` 注释）。标定实测：

| 档 | 参数 | 结果 |
|---|---|---|
| `stealth` | `route_pen=2000, exposure_pen=1000` | 长距离路网占比 **89% → 6~11%**，耗时 **1.70~1.72×**（达标）|
| `safe` | `danger_w=1500` | 主动降路网（89%→55%、87%→42%），火山格 +12.5%、峡谷格 +19.4% |

⚠️ **但"最安全"仍兑现不了设计承诺，且原因不是标定，是数据模型**：

- 实测 **`fastest` 在 90% 的城镇对上危险里程 = 0**（60 对抽样：54 对完全不含危险地形）；
- 剩下 10% 里，`safe` 也无法降低危险里程（反复扫描 `danger_w` 1500→30000：危险里程 4845→5323 里，
  **只增不减**，耗时却 1.0→3.2×）；
- **根因**：`Terrain.danger` 与"慢"高度相关（火山 4 里/日 danger 0.9、官道 44 里/日 danger 0.0），
  所以 **`fastest` 本来就在避开危险地形**——时间项已经替 `safe` 干完了活。
  `safe` 只能靠绕远再规避一次，而没有任何可规避的余地。

**结论与处置**：`danger_w=1500` 保留为**极端地形护栏**（火山带不至于被硬穿），
但"最安全"这一档的**语义必须由后续设计补**——危险应当**与速度正交**（如"路好走但有劫道"
"平原开阔但妖兽多"），那是**遇敌/动态实体模型（P7）**的事，不是能靠调系数解决的。
**本任务书据此把判据 1/2 改为"可判定且不依赖不成立的假设"**（见 §四）。

## 二、字段级规格

### 2.1 代价模型改线性组合（`engine/worldmap.py`）

```python
# 现在（乘在速度域）：
cost = w / sp * inv_si * mult          # mult = 1 + 3×danger（被 9 点 min 抹平）

# 改为（时间项 + 危险项，代价域相加）：
_e_li = _CELL_LI * ox_or_oy_scale      # 采样点对应的实际格内尺度
t_cost = _e_li / sp * _SI_PER_DAY * mult_time     # mult_time 只含 road_mult / forest_mult
d_cost = danger_w * R.TERRAINS[tid].danger * _e_li
cost = t_cost * (1 + slope_pen×…) * (1 + jitter×…) + d_cost
```

- `danger_w` 作为 **profile 参数**（`PROFILES["safe"]["danger_w"]`），不再硬编码 3.0。
- **危险项与时间项同量纲（息）**，所以 9 点取 `min` 不再抹平它：绕开危险地形必然省钱。
- `stealth` 的 `road_mult` **从速度域乘区改为代价域加罚**，并重标（原 6.0 导致 +55% 时间）。
- `speed_at()`（对外 API）语义不变：仍返回地形速度；危险/暴露属**代价**，不进速度。

### 2.2 A\* 启发式必须重新可采纳

启发式原来只有时间项（`cell_li / max_speed`）。加了危险项后必须同步加上下界，
否则 A\* 可能不再最优：

```python
# 每格上界：危险项 ≥ 0，故用 max_danger 给出下界
h = (li / max_speed × SI_PER_DAY + danger_w × max_danger × step_cells)   # step_cells = max(1, li/field_li)
```

- `max_danger = max(t.danger for t in R.TERRAINS.values())`（当前 0.9，火山熔岩）。
- **只在 `danger_w > 0` 的 profile 上加**，其余档保持原启发式（零成本）。
- 验收：仍与独立 Dijkstra 一致（判据见 §四）。

### 2.3 三档候选 + 执行（两段式）

新增动作（**扩展现有 `travel`，不新建动词**，避免 CLI/Web/测试三处重复）：

| 动作 | 行为 |
|---|---|
| `travel`（不带 `go`） | **预览**：返回 2–3 条候选（结构化 `data.routes[]`），**不推进时间、不移动** |
| `travel` + `route=<idx>` | **执行**选中的候选：按 `total_si` 推进时间、更新位置 |

候选档位按**舆图档位**给（定案 §5：地图分三档）：

| `map_level` | 候选 |
|---|---|
| `none`（无舆图） | 不给候选——只给"手动探路"（§2.4） |
| `coarse`（粗舆图） | `fastest` 一条 |
| `detailed`（详图） | `fastest` / `safe` / `stealth` 三条 |

每条候选的结构（`data.routes[]`）：

```python
{"idx": 0, "profile": "fastest", "label": "最快",
 "days": 446.0, "si": 19266034, "li": 13650.0,
 "terrain_mix": {...}, "danger_share": 0.31, "exposure_share": 0.12,
 "on_road_share": 0.68,        # 官道+小径占比（"沿路 / 越野"的可见口径）
 "dest": {"id": "town_青石镇", "name": "青石镇", "x": 10000.0, "y": 10000.0}}
```

### 2.4 手动探路（无舆图）

```python
def _march(self, direction: str, steps_hint: int = ...) -> Result
```

- `direction` ∈ 八方向（`北/东北/东/东南/南/西南/西/西北`，与 `_SLOPE_OFFS` 同口径）。
- 从当前位置沿直线推进，**逐 1 里采样**：累计时间 `Σ ds / speed(terrain)`；
- **遇硬阻挡（`R.HARD_BLOCK_IDS`）或水域（`T_WATER`，含不可渡）→ 停在该点前，返回 `blocked` + 挡路地形**；
- 单次推进上限 `MARCH_MAX_LI`（默认 **300 里**，≈ 练气 14 日），避免"一格跨半个世界"；
- **绝不调用 `find_path`**（不自动绕行）——这是"无舆图"的核心语义。
- `T_FORD`（渡口）可通行；湖泊/河流按 `swim_only` 与境界判定（练气不可渡）。

### 2.5 存档迁移（世界位置进存档）

| 项 | 现在 | T3 |
|---|---|---|
| 玩家位置真相 | `Player.location`（地点 id，5 个扁平地点） | **`GameState.world.pos`（世界坐标）** |
| 位置标签 | 同上（直接当真相用） | `Player.location` 降级为**派生标签**（移动后同步），前端契约与 smoke 不受影响 |
| 序列化 | 只有 `player.location` | `GameState.to_dict()` 增 `world` 键（`WorldState.to_dict()`，**恰 6 键**） |
| 老档 | — | 无 `world` 键 → `WorldState.legacy(seed, location=旧地点名)` → 锚点坐标（已实现） |

- **不存地形 / 路网 / 探索度位图**（定案 §7）。
- `state_data()["location"]` 扩展为 `{id, name, x, y}`（前端 `LocationInfo` 加可选 `x`/`y` 不破坏现状）。

### 2.6 时间接真

- `_travel` 里 `S.TRAVEL_DAYS` **废弃**（`settings.py:156` 的常量标注删除，或留常量但不再被移动使用）。
- 移动耗时 = 候选 `total_si`（战斗中/闭关一律走同一条 `_advance_si`，T1 已完成）。
- 到达后 `p.location` 同步为新坐标最近的城镇；`explore` 的"先移动到该处"同样改按路径耗时。

## 四、验收判据（逐条可判定 + 证据）

| # | 判据 | 证据 |
|---|---|---|
| 1 | **代价域口径**：`safe` 对危险地形加价 ≥10%、对无危险地形**零加价**（危险项与时间项正交）；加价随里程线性 | 单测（`test_worldmap` G50b/c/d，已通过） |
| 2 | `safe` 耗时 ≤ `fastest` × **2.0**（不再允许"绕 2.8× 却一点没绕开"） | 单测 |
| 3 | `stealth` 的路网占比 ≤ `fastest` × 0.5，且耗时 ≤ `fastest` × **1.8** | 单测（实测 6~11% / 1.70×） |
| 3b | ⚠️ **不得**断言"`safe` 的危险里程显著低于 `fastest`"——实测该假设**不成立**（90% 的 path 本就不含危险地形；10% 里无从规避）。该档语义待 P7 危险模型补 | 记录在 §0.2，防后会话照旧标准验收 |
| 4 | **A\* 仍最优**：`danger_w > 0` 的档与独立 Dijkstra 代价一致（±1 息） | 单测（沿用 `_dijkstra` 对照） |
| 5 | 移动耗时 = 路径 `total_si`（与距离/地形/境界一致，不再是固定 3 日） | 单测：同一起终点换境界档 → 耗时单调下降 |
| 6 | `travel` 预览**不推进时间、不移动**（纯查询） | 单测：前后 `state.t` 与 `pos` 不变 |
| 7 | `travel route=k` 执行后位置 = 候选终点，`t` 增加 `si` | 单测 |
| 8 | `map_level=none` → 不给候选，只接受 `march`；`coarse` → 1 条；`detailed` → 3 条 | 单测（三档各一） |
| 9 | **手动探路遇硬阻挡 / 水域停下**：从已知阻挡旁的起点按方向推进 → `blocked=True` 且 `data.blocked_by` 为对应地形名 | 单测（找一格硬阻挡样本） |
| 10 | **手动探路绝不自动绕行**：`march` 的路径格与直线栅格化结果一致（无拐弯） | 单测 |
| 11 | 存档往返：`world` 键恰 6 个；载入后 `pos` 一致；**旧档（无 world 键）** 迁移到锚点 | 单测 |
| 12 | smoke 20 局指纹：**预期变化**（移动耗时从 3 日变成真实路径日），必须记录新基线并说明原因 | `tools/replay --compare` + 人工确认 |
| 13 | 全量 `main.py test` 全绿 | 退出码 0 |

> 判据 12 是**唯一允许的指纹变化**，原因：`travel` 的耗时从 `TRAVEL_DAYS=3` 变为真实路径耗时，
> bot 的时间线、年龄、寿元压力必然改变。**这是 T3 的目的，不是回归。**
