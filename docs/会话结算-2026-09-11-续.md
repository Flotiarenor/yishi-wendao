## 三、地图坐标朝向 bug（本次最重要的发现）

### 3.1 现象

用户报两件事，当时看像两个 bug，其实是**同一个**：

1. **右键"走到那里"像是偏的**；
2. **底图上的城镇点与可点击的城镇点不重合，甚至有的落在湖里**。

### 3.2 排查过程（这一段本身就是教训）

我先按"点击 → 反解 → marker"这条链测，**全部精确**：

| 检查项 | 结果 |
|---|---|
| 点击位置 vs 目的地 marker 圆心 | **Δ = 1 px**（真 Edge 截图 + 逐像素量红/蓝标尺） |
| 点击坐标反解 → 再正投影回屏幕 | 逐位一致（`SIZE=560 / PAD / radius_li=4000` 全核过） |
| 引擎落点 vs 请求坐标 | `_set_pos_arrived(gx, gy)` 就是**原样**请求的坐标 |
| 走完后的底图中心 | 正好等于落点 |

**为什么一直测不出来**：我核对的都是**视图中心附近**，而**y 轴翻转在中心点是恒等的**
（`y - cy = 0` 时 `-(y-cy) == (y-cy)`）。所以"中心附近一切正常"恰恰是这个 bug 的特征。

突破口是用户那句"**底图的城镇坐标和可点击的点不重合**"——它把问题从"点击链路"指向了
"**两层渲染的坐标系**"。于是换成问服务端要两份真值对照：

1. `state_data()["map"]` 里的城镇世界坐标（**SVG 叠加层用的就是这份**）；
2. **同一张底图**（同 seed/中心/span/px），再用"把 `_towns` 清空再渲一次"的**差分**
   隔离出「城镇层」，得到底图上城镇**实际画在哪个像素**。

结果一望即知：

| 城镇 | 前端投影像素 | 底图实画像素 |
|---|---|---|
| 青石镇 (10000,10000) | (280, 280) | (280, 280) ← **中心恰好重合，骗过了所有中心附近的检查** |
| 东海关 (12304,7715) | (426, **425**) | (441, **120**) ← Δy = **−305 px ≈ 9 600 里** |
| 落雁镇·二 (11036,13201) | (346, **77**) | (353, **504**) ← Δy = **+427 px** |

### 3.3 根因

定案 §3.1 写明「坐标 `(x, y)`，单位里，**原点西南角**」→ **y 越大越靠北**；
而屏幕像素 **y 越大越靠下**。所以世界→屏幕**必须翻转 y**。

- ✅ **前端做对了**：`MapScreen.vue` 的 `sy = -((y - self.y) / R) * half`；
- ❌ **三处渲染器都没翻**：
  - `tools/atlas.py` 的 `w2p()`（**游戏内底图**用的就是它）
  - `tools/maprender.py`（实景风，`to_px` 与细档采样）
  - `tools/mapview.py` 预览的 HTML 前端（地形行 + 河/路/城镇叠加）

**为什么能活这么久**：四处各写各的投影公式，谁也没和谁对过；
而**只核对视图中心时两者恰好重合**。这正是交接文档里反复强调的那类
"**判据必须与引擎同口径**""**同一语义只能有一处实现**"的风险。

### 3.4 修法

| 文件 | 改动 |
|---|---|
| `tools/atlas.py` | `w2p` 的 y 改为 `(y0 + span - y) * k`（并把理由写进 docstring） |
| `tools/maprender.py` | `to_px` 同式；细档采样 `y = (cy + half) - (j + 0.5) * step`；**快档 `terrain_surface_fast` 行序倒置**；快档裁切的源矩形上边改用 `cy + half` |
| `tools/mapview.py` | HTML 里加 `Y = (wy) => PX - wy * s`，河/路/点/城镇四处改用 `Y(...)` |
| `frontend/src/views/MapScreen.vue` | **第二处错位**：底图把 `span` 铺满 `SIZE` 像素，而叠加层把同一个 `span` 挤进 `SIZE - 2*PAD` → 同一个世界坐标在两层落在不同像素（离中心越远差越多）。**删掉 `PAD` 内缩，统一用 `HALF = SIZE / 2`**（`px`/`unpx`/`gridLines` 三处同源） |

修完实测：

| 指标 | 修前 | 修后 |
|---|---|---|
| 底图城镇与前端投影像素**命中**（≤3px） | **1 / 206** | **22 / 22** |
| 残差分位 p50 | 10.0 px | **1.5 px**（整圆取整误差） |
| Δ 均值 y | **−28.3 px** | **−0.96 px** |

> 残留的 ~1px 是"圆心取整到整像素"的固有误差（城点半径 5），不是错位。

### 3.5 教训（沿用并补充铁律）

1. 📌 **同一语义只能有一处实现**——投影公式在两个语言（Python 渲染 + 前端 SVG）里各写一份，
   就必须有**一条测试把两边钉在一起**，否则迟早朝向/比例分叉。
2. 📌 **验收不能在"恒等点"上做**：y 翻转在视图中心恒等，缩放比例在中心也恒等。
   判据必须**远离中心**（本次抽样专门挑"离世界中心 1500 里以上"的城镇）。
3. 📌 **判据要能证伪**：本次立住的判据是"同屏取一南一北两座城镇，北边的屏幕行号必须更小"
   —— 若朝向反了，两者必然互换，判据立刻红。
4. 📌 **别用"找最大墨团"当几何判据**：路网/河流/地貌母题/地名笔画都会污染质心，
   实测误差可达 9px（是**检测噪声**，不是 bug）。要么用差分隔离图层，要么用可证伪的次序判据。
5. 📌 **排除目录的 `.gitignore` 会吃掉反向规则**：`logs/` 排除后 `!logs/map_baseline.json` **静默失效**，
   必须写成 `logs/*` 再 `!logs/map_baseline.json`。

## 七、用户实测反馈与返工（**最该记住的一节**）

用户实际玩过之后报了六条，其中两条暴露了我的**验证方法**有系统性缺陷：

| # | 用户反馈 | 真因 | 教训 |
|---|---|---|---|
| 1 | "两张图除了位置不一样没什么区别、浏览器里也没看到实景" | **功能是好的，量太小**：一次 travel 只在**落点那一格**写 explored → 走 3 段 = 4 格 = **36 像素 = 0.01%** | ① 我的验证是"在 Python 里自己调 `render_atlas`"，**绕过了 HTTP + 前端 + 浏览器**整条链路；② **"像素有差异"不等于"看得见"**——判据要带**量级**（占比），不能只判 `diff > 0` |
| 2 | "右键只能进入野外，进城要左键→查看路线→选候选" | 交互设计把"去某处"拆成了两条路：右键一套状态、点城镇一套状态 | 同一个概念两套状态 = 迟早行为不一致。**合并后两个 bug 在结构上消失** |
| 3 | "先进了城，上一次的路线还在、时间也不变" | 同上（两套状态没人负责清理） | 同上 |
| 4 | "图例里'舆图/实景/已踏勘'那行没有意义、多余" | 我把"实现细节"当成了玩家需要的说明 | **别把内部机制写进玩家界面**——玩家当然知道探索开的是实际图 |
| 5 | "地图不支持缩放" | **缩放是好的**（E2E 都过），但我的判据只查"城镇点变多"，**没查底图 `<image>` 的 href 与像素**——那才是玩家眼里的"图变了没有" | 判据要**对齐玩家的感知通道**：玩家看的是图，不是 DOM 里的点数 |
| 6 | "地图不铺满屏幕" | `max-width: 560px` 写死 | 纯疏漏。顺带发现"铺满后底图 `px` 必须跟着显示尺寸走"，否则大屏上是糊的 |

**共同教训（比单个 bug 值钱）**：

1. 📌 **别在"自己那一侧"验证跨层功能**。我验证渲染 = 在 Python 里调渲染函数；
   用户看的是**浏览器里的那张图**。跨层的东西一定要**在真实链路上量**
   （本次把判据搬进 `tools/e2e_web.py`：读 `<image>` 的 href、取回浏览器实际收到的 PNG）。
2. 📌 **"有差异"≠"看得见"**：判据要带量级（占比 / 像素数），并明确阈值。
3. 📌 **同一个概念只留一套状态**。两套状态描述一件事时，bug 会在"没人清理的那一侧"冒出来。
4. 📌 **界面文案是给玩家的，不是给实现者的**。
5. 📌 **判据要对齐玩家的感知通道**（看图 vs 看 DOM），否则测试全绿而用户说"没反应"。

**改代码时的铁律（沿用并补充）**

- 改地图/城镇内容 → `terrain_checksum` 与相关断言需**重基线**，属预期；改完**必须跑全量 + smoke**
- **不要**把路/河写回地形数组；**不要再引入全图高精度数组**
- `engine/`、`content/` **永不 import pygame**；渲染只走 `present/` 与 `tools/`
- 📌 **新增**：**世界→屏幕的 y 必须翻转**（原点在西南角）。动了任何一层渲染，

- 📌 **新增**：验收别在**恒等点**（视图中心）上做——朝向、缩放的问题在中心都看不出来

- 📌 **新增**：**同一个概念只留一套状态**（"我要去某处、有这几条路"只能有一个 `plan`）
