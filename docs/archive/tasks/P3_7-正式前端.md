## 目标

把 `server/static/` 的极简面板升级为**可长期演进的正式前端**：

- 新工程 `frontend/`（Vue3 + Vite + Pinia + TypeScript），构建产物 `frontend/dist`；
- FastAPI 伺服 `dist` + SPA fallback（`/api` 404 不被吞）；
- **中置战斗界面**：时间轴 + 决策窗口 + 动作队列（R3 语义，不是「点一下打一轮」）；
- **地图 / 坊市独立界面**：地点节点 + 移动/探索；货单 + 背包 + 购买数量；
- 修掉 P3.6 面板的 A 类真 bug（见 §D 缺陷清单）。

**明确不做**：玩法/数值改动、新 API 端点（除静态伺服外）、pywebview 桌面壳（阶段3）、
行动条「插队/推拉条」复杂交互（定案 §十二红线）、手牌/抽牌（红线）。

## A. 服务端唯一改动

### A1. 静态伺服切换到 dist

```python
# server/app.py
_STATIC_DIR = .../server/static          # P3.6 旧面板（保留为降级）
_DIST_DIR   = .../frontend/dist          # P3.7 正式前端

# dist 存在 → 伺服 dist；否则回退 static（旧面板仍可玩）
```

要求：
- SPA fallback 用 `StaticFiles(html=True)` 语义；`/api` 前缀 404 必须仍是 JSON（P3.6 已验收，勿回退）。
- 前端路由建议 `history` 模式 + 服务端 fallback；若实现成本高，允许 `hash` 模式（需在报告中说明）。
- `config` 仍支持 `{"save_dir": ...}`；**不新增任何 `/api` 端点**。

### A2. 修 `gongfa_detail` 500（真 bug，本轮必修）

现状：`content/skills.py` `SkillSpec.element` 假设「首个组件是 Damage」：

```python
return self.action.components[0].element if self.action.components else "无"
```

组件是 `ApplyStatus` / `QiGain` 时无 `.element` → `AttributeError` → HTTP 500。
**实测 12 本功法里 7 本崩**（玄水真经/青木功/厚土诀/锐金典/御风步法/吐纳诀/撼岳诀），
**含开局必有的吐纳诀**——前端「书库→详情→装备」主流程直接被阻断。

修法（择一，报告写明）：
- 取**首个含 element 的组件**（`Damage` 优先）作为展示元素；全无则 `"无"`；
- 或 `getattr(c, "element", None)` 兜底扫描。

验收：`gongfa_detail` 对 **全部 12 本**功法 `ok=True`，且新增测试锁死（防回归）。

## B. 前端工程 `frontend/`

```
frontend/
  package.json  vite.config.ts  tsconfig.json  index.html
  src/
    main.ts  App.vue
    api/        client.ts（fetch 封装 + 统一响应类型）
    types/      contract.ts（state_data / battle.state / market / gd 的 TS 类型）
    stores/     session.ts（run/state/日志） battle.ts  ui.ts（面板开关）
    views/      StatusPanel.vue  ActionPanel.vue  NarrativeLog.vue
                BattleScreen.vue  MapScreen.vue  MarketScreen.vue
                LibraryScreen.vue  ChronicleScreen.vue
    components/  Bar.vue  Toast.vue  Modal.vue  …
    styles/      tokens.css（沿用 P3.6 深色配色，抽成变量）
```

约定：
- **无 CDN**（离线可跑，与项目「零运行时外部依赖」一致）；依赖装进 `frontend/node_modules`。
- `fetch('/api/...')` 同源，不引入 CORS。
- **成败只看 `ok/reason`，禁止解析 `text`**（P3.6 铁律，`tests/test_server.py` 已有断言）。
- `text/lines` 只进叙事日志流。
- 所有金额/时长显示单位：灵石「枚」、时间「息（厘息/100）」。

## C. 三个核心界面（用户拍板形态）

### C0. 主布局（2026-09-09 用户拍板，含后续修订）

```
┌──────────┬──────────────────────────────┐
│          │  中上：主内容区               │
│ 左：状态  │   地图（默认）/ 修炼 / 战斗接管 │
│ （常驻）  │   / 坊市 / 书库 / 编年史       │
│  + 切换   ├──────── 拖拽分隔条 ──────────┤
│   按钮    │  中下：叙事日志（高度可拖拽）  │
└──────────┴──────────────────────────────┘
```

- **没有行动栏/右栏**（用户第二次修订：日常动作直接进主页面）——闭关/参悟/突破/静养
  收进**修炼页**（主内容区视图），状态栏加「修炼」切换按钮（在「编年史」左边）；
- **地图是主页面**（默认视图）；战斗**临时接管**同一块区域，打完自动交还地图；
- **叙事日志常驻中下**（可折叠）——探索/战斗的文字必须一直看得见，**禁止用覆盖层挡住日志**
  （首版把地图/坊市做成覆盖层，探索后看不到文字，已修正）；
- **中上/中下之间的分隔条可拖拽**调整日志高度（双击复位 240px），高度存 localStorage；
- 状态栏保留查看入口（地图/修炼/坊市/书库/编年史），**不在别处重复**；
- **参悟目标要记住**（store + localStorage），状态刷新不得把下拉打回第一项。

### C2. 战斗界面 `BattleScreen.vue`（重点）

`state.battle` 非空时**临时接管主内容区**（不是右侧小面板，也不是覆盖层），自上而下：

| 区域 | 内容 | 数据源 |
|---|---|---|
| 双方状态（最上，常用） | HP/灵气条 + `qi_rate`/`speed`/`stones` + **效果列表**（key/剩余时长/层数） | `player / enemy / effects.player / effects.enemy` |
| 时间轴 | 玩家/敌方 `next_t` 标记、当前 `t`、队列动作的 `end_t` 落点、窗口区间 | `t / player_next_t / enemy_next_t / queue[].end_t / window_li` |
| 常用动作 | 平砍/防御/聚气/遁走 + 「执行本轮」（`battle_skip`） | `actions[]`（按 key 取基础四式） |
| 技能（折叠） | 点「全部技能」展开：名称/耗灵/前摇/后摇/品阶/**可用性与原因** | `actions[]`（`available`/`reason`/`desc`） |
| 队列 | 已排动作、每个动作的 `end_t`、累计时长 vs `window_li` | `queue[]` + `window_li` |
| 返回 | 「回地图（战斗继续）」——战斗未结束也可切回地图看叙事 | `ui.closeBattle()` |

硬要求：
- **不得**再把 `battle_action` 当作「点一下打一轮」的唯一入口——必须体现
  「入队（`battle_submit`）→ 窗口满或点执行（`battle_skip`）→ 结算」的 R3 语义；
- 不可用动作**必须禁用并显示原因**（`reason` → 中文，缺码回退显示原文码）；
- 战斗中其余日常动作（闭关/参悟/移动…）**整体锁定**并有明确提示，不能只是变灰；
- 战斗结束（`battle` 变 null / `battle_over`）时给出结算提示（胜/败/逃）并**自动交还地图**。

## D. 缺陷清单（P3.6 面板已确认的真 bug，必须在 P3.7 消除）

1. 战斗面板字段全错：读 `b.enemy_name/b.p_hp/b.turn/b.skills`，真实为 `b.enemy.*/b.player.*/b.t/*`、
   `b.actions[]`（实测血条恒 0%、回合 undefined、技能按钮为空）；
2. `#btn-pill` 无事件绑定（死按钮）；
3. `st.day` 不存在 → 「日 undefined」；
4. 失败响应不带 `state` → 界面与引擎状态不一致残留；
5. 硬编码地点/槽位/`FAM_MAX`/`REASON_TEXT`（改引擎必漏）；
6. `busy` 不禁用 UI → 连点会重复发请求（战斗里等于连打）；
7. 下拉框每次重渲染被重置（选中项丢失）；
8. 无响应式布局、`calc(100vh - 53px)` 魔法数字、右栏内容会被裁且无法整页滚动；
9. 刷新丢日志；无 loading/无禁用态；破坏性操作无二次确认。
