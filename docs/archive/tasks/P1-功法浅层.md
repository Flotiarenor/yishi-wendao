## 任务目标

让"功法 = 战力载体"成立（技能先只落数据，P2 战斗才使用）：
- 建 技能 与 功法 两个 content 文件（30 段 / 40 段）
- Player 加"功法栏"（运转池雏形：主修 1 个，本任务只开放主修位）
- 主修功法的被动（修炼效率加成）聚合进闭关修炼
- 开局按灵根赠一本主修功法；坊市可购买功法
- 旧档迁移：无功法字段的旧档载入后赠一本主修

**明确不做**（属 P3）：理解锁、参悟/熟悉度、技能需求谱系生效、战斗槽(4)、身法槽(2)开放、技能实际施放。技能实体只需存在并被功法引用，供面板展示。

## 规格

### A. content/skills.py（30 段）

仿 pills.py 结构（id 常量 + dataclass + PILLS/SKILLS 注册 + ID_BY_NAME + resolve + name_of + by_id）。注意段常量 `CAT_SKILL = 30`（在 ids.py 已存在）。

Skill 字段（dataclass, frozen=True）：
- `id: int`、`name: str`
- `element: str`（五行："金"/"木"/"水"/"火"/"土"/"无"）
- `kind: str`（"attack"/"defense"/"utility"，P1 仅数据）
- `qi_cost: int`（灵气消耗，P2 用）
- `power: int`（攻击基准，P2 用；非攻击技能可 0）
- `requirement: str`（谱系 "free"/"gentle"/"strict"，P1 仅数据）
- `desc: str`

至少 8 个示例技能，与下面功法配套（如火系"烈焰斩"attack/gentle、木系"青藤缠"utility…自由发挥但要能覆盖金木水火土各一）。

### B. content/gongfa.py（40 段）

Gongfa 字段（dataclass, frozen=True）：
- `id: int`、`name: str`
- `slot_type: str`（"main"/"battle"/"shenfa"——本任务只允许 main 进栏，另两种仅数据）
- `element: str`（主五行倾向）
- `tier: int`（境界层级参照：10/14/18/22 对应筑基级/金丹级/元婴级/化神级；练气级=1。P1 仅数据展示）
- `price: int`（坊市售价灵石）
- `cultivate_bonus: float`（修炼效率加成，叠加：最终效率 = root_mult × (1 + 主修 cultivate_bonus)）
- `skill_ids: list[int]`（0~4 个，引用 skills.py 的 id 常量）
- `desc: str`

示例功法 ≥6 本，覆盖：
- 主修类：火(炎阳诀, cultivate_bonus 0.3)、水(玄水真经, 0.35)、木(青木功, 0.25)、土(厚土诀, 0.3)、金(锐金典, 0.35) 各一本，分别挂 1~2 个对应五行技能；练气级( tier=1 )便宜(150~300)，另 1 本筑基级主修(如"焚天诀" tier=10, bonus 0.8, price 1500, 带 3 技能)——让"坊市买更好功法"成为成长点
- battle/shenfa 各至少 1 本（仅数据，价格合理即可）

### C. Player 加功法栏（engine/state.py）

新字段（给默认值，保证旧档 from_dict 兼容——它已按字段过滤）：
- `main_gongfa: Optional[int] = None`  ← 存功法 id
（battle/shenfa 槽本任务不加字段，P3 再加；避免反复改存档结构）

### D. 修炼聚合（engine/game.py）

`_cultivate` 中效率计算改为：
```python
mult = p.root_mult
if p.main_gongfa is not None:
    gf = G.by_id(p.main_gongfa)      # G = content.gongfa
    mult *= (1 + gf.cultivate_bonus)
```
闭关文本在用了主修功法时附注（如"（主修【炎阳诀】加持 ×1.30）"）。

### E. 开局赠功法 + 旧档迁移

- `_new_player` 末尾：按主灵根送一本对应五行主修功法并 `p.main_gongfa = 该id`（火→炎阳诀…五本对应；无匹配给土系或第一本）。
- `_migrate_state`（旧档）：若载入的存档 player dict 里**没有 main_gongfa 键** → 按灵根赠一本（与上面同一 helper `_gift_main_gongfa(p)`）。存档有该键（即使是 None=玩家主动卸下）则不动。
- 迁移函数需要知道"存档原文是否含此键"：在 `Game.__init__` load 分支里 `had = "main_gongfa" in (load.get("player") or {})` 传入 `_migrate_state(had_gongfa=had)`。

### F. 新动作与 CLI

engine 动作（仿现有风格，返回 Result）：
- `"learn" {gongfa}`：解析 id；若非 main 类提示"此功法暂不可装备（P3 开放）"；main 已占用提示先 forget；否则 `p.main_gongfa = id`，记编年史
- `"forget"`：卸下主修（置 None），记编年史
- 面板 `status` 增加一行：`主修功法：{名}（加成×{1+bonus:.2f}）` 或 `（无）`

CLI（cli/main.py）：
- 菜单与解析加：`g 功法名`(learn) / `gf`(forget) / 状态里已显示主修
- buy 支持功法：`buy 炎阳诀 1` —— engine `_buy` 里解析顺序 pills → gongfa；功法购买直接入账（无背包概念，装没装备由 learn 决定；购买后记"已购得"）。功法不需要进 inventory（inventory 目前是丹药计数 dict；功法购买即"拥有"，learn 不受 inventory 限制——简化：能买就能学）。给 status 加一行显示已购功法？不必：P1 简化 = buy 功法后提示"可在坊市货单见其简介，用 g 装备"。为避免歧义，货单 market 列出功法（带价格/五行/技能数简介）。
- 菜单文档同步更新。

### G. 测试与平衡

- `tests/smoke.py`：闭关天数估算需含主修加成，否则 bot 会反复小步闭关低效（把估算改成 `S.BASE_DAILY_EXP * p.root_mult * (1+主修bonus)`；新增 helper 或直接读）。其余逻辑不动。
- 平衡注意：开局赠的练气级主修 bonus 在 0.25~0.35 之间（不要破坏 P0 的"废灵根有寿元压力"分布——P0 基准 root_mult 已含出身）。跑 `python -X utf8 -m tests.smoke` 20 局，通关/道陨分布应仍在合理范围（不必与旧值相同，记录新分布即可）。
