# 一世问道 · 设计定案（工作文档）

> 本文档是**唯一权威的设计依据**。所有决策在对话中锁定后同步于此；修改设计 = 修改本文档。
> 状态图例：✅ 已锁定 ｜ ⚠️ 待定 ｜ 🔧 扩展位（第一版不做）

---

## 一、核心原则（一切设计的基石）

1. ✅ **这是一个真正的游戏，不是 AI 交流工具**。运行时**零 AI**：规则、数值、随机全部由确定性代码裁决（可复现、可测试、不偏心）。
2. ✅ **状态机与叙述分离**：游戏状态 = 存档里的数据结构；文字只是状态的渲染。记忆问题从根上消失。
3. ✅ **"更像游戏"的三要素**：不可逆（决定不能白嫖重来）、信息不对称（玩家看不见全部底牌）、代价可感知（每个选择烧掉真实有限资源）。
4. ✅ **素材层与机制层分离**：MCP/AI 那批世界观数据（五层灵力理论、145 属性、品阶表…）是**素材/皮肤/内容生成约束**，不是引擎机制。引擎只认薄结构。
5. 🔧 AI 的可能位置（当前不用）：离线批量产内容草稿（经规则校验后入库）；运行时旁白（只翻译结果，无权改结果）。

## 二、时间、寿命与存档

- ✅ **时间按天计算**，一天是最小单位；世界每天推进。
- ✅ **闭关 = 玩家自选 N 天**（如 30/100/365），引擎直接结算 N 天；期间可插入事件（心魔、顿悟、仇家上门、灵气潮汐），世界演化照常流逝。
- ✅ **一世一档 roguelite**：寿元驱动。每世一个存档，寿元耗尽/道陨即终局。
- ✅ **存档 = 固定种子 + 节点回溯（杀戮尖塔式）**：每局固定种子；在"节点"（突破尝试前/重大抉择前/闭关开始前）自动存档；回档 = 退回上一个节点，不能跳到任意过去。
- ✅ **随机流实现**：种子固定后所有随机是一条随机数流，存档记录"取到第几个"。回档 = 游标退回 → 不改选择重试结果相同（防无脑 SL），改选择结果自然不同。
- 🔧 "拨动天机/重 roll 某事件"的道具：实现上是跳过/重抽随机流一段——第一版不做，留扩展位。

## 三、死亡、残废态与转世

- ✅ **一世内有残废态（不一步到位）**：重伤/丹田碎裂/废功法等"半死"——境界跌、寿元大减、功法废掉，但人活着，可带残躯走完余下岁月或缓过来重来。死亡依然是终点但更少直接触发。
- ✅ **无 meta 成就继承**：不继承上世的功法/技能/灵石/遗产。
- ✅ **继承"起点"而非"成就"**：转世 = 继承 体质/悟性/气运/出身 等"下世的开局条件"，每世仍从零亲手打出来。
- ✅ **转世点数按本世成就结算**：走多远（境界）、功德、大事纪 → 决定下世能花多少点、解锁哪些起点选项。给"尽量活久/活好" meta 层面理由。
- ✅ **业力不跨世**：每世善恶清零；功德/业力的机制只在**局内**生效（影响突破天劫等）。
- ✅ **开局资质 = 固定点数池 + 玩家自选搭配**：转世结算给点数，玩家在开局界面自己花点配 体质/悟性/气运/出身 等，非随机出生。

## 四、物品模型（双轴分类，非武器中心）

**轴一：功能** —— 这东西干什么用
- **战力类**：功法 / 武器 / 法宝 / 防具（影响打多狠、扛多住）
- **功能类**：储物 / 飞舟(遁行) / 辅助修炼灵珠 / 材料 / 杂物（影响带多少、走多快、修多快）

**轴二：门槛长在哪个环节**
- ✅ **功法 = 理解锁**：境界不到**看不懂**，无法用蛮力绕过，没有"强行"选项。
- ✅ **器物 = 力量锁，宽松**：拿得起就有用（物理底子），无需境界。
- ✅ **功能类 = 无门槛**：限制是价格与稀缺性，不是境界。

### 器物（极简）
- ✅ 器物线：锋利/坚固等物理底子，**无属性**，纯平砍价值。
- ✅ 偶尔自带 1 个神通，按**大境界**整体点亮（无逐条灰）。
- ✅ **无反噬、无强行催动**——整套机制删除（那属 AI 素材层遗留，抄不动，砍）。
- ✅ 武器不是必需品：拳修/体修等流派不需要武器。

### 功法（本游戏核心系统）
- ✅ **理解锁**：境界不到 = 看不懂（只有书名/品阶/来历，不知内部技能与属性）。
- ✅ 完整链条：**获得 → 看懂(境界够) → 参悟(花时间，正式"学会"可入池) → 运转(占槽生效) → 持续参悟+战斗使用 → 熟悉度上涨 → 逐层解锁技能 + 小幅面板加成**。
- ✅ 参悟是**持续修炼**而非一次性入场券：闭关天数投给修为还是投给某本功法参悟，本身就是抉择。本命功法越养越强。
- ✅ 一本功法带 **1–4 个技能**。
- ✅ **两池分离**：
  - 领悟池（无限）：学过/看懂过很多功法，永久累积（技能进总技能库；被动作为道基累积？→ 见"运转"规则）
  - 运转池（有限槽）：主修 **1** + 战斗 **4** + 身法 **1–2**
- ✅ **不在运转池的功法完全不生效**（A 方案）：学得多只增加选择面，不增加战力。槽位竞争 = 核心决策。
- ✅ 功法三类并存：**纯被动 / 带适配技能 / 纯技能整理**——不压进统一模板。
- ✅ 战前构建三层动作：挑运转功法（被动组合）→ 从领悟的总技能库编 12 格出战 → 调身法。
- ✅ **"余位被动"层（新想法，用户提出）**：存在一类**不占主运转槽位、但常驻生效的被动**（如敛息术、气机遮蔽类）——它们从功法参悟中获得，独立于 1+4+1~2 槽位体系之外生效，常用于宝光公式的"被动终乘"层或全局修正。🔧 细则（获取途径/上限/与运转池关系）待设计。

## 五、技能与需求谱系

- ✅ **技能需求 = 一条谱系，不是一刀切**：

| 需求等级 | 机制 | 例子 |
|---|---|---|
| 无需求（自由） | 学会即永久归你，随时可编组，与功法无关 | 顿悟招式、基础术法、体修拳脚、前辈灌顶 |
| 温和 | 亮出后母功法**在运转池任意槽**即可用 | 门派大部分传授功法 |
| 严格 | 母功法在**主修/特定槽**，或熟悉度达大成才解锁 | 镇派绝学、秘传终式 |

- ✅ **自由技能天生弱**：通常辅助类/简单攻防，人人可得，**无需限量**（不存在绕过羁绊问题——它和功法技能不同源）。
- ✅ **出手层 = 12 格纯技能栏**；**基础动作固定在场外、不占 12 格**（平砍/防御/遁走/聚气始终可用）。"12 格不含基础动作，但基础动作始终有"。
- ✅ **聚气指令：要**；同时**保留每回合自动回复的基础部分**。灵气回复双轨：回合自动回基础量 + 聚气（放弃本回合出手、额外大幅回复）。
- 🔧 "整理类功法把外来技能写入自身 → 变自由技能"：降级为扩展位，第一版不做。

## 六、战斗（手操 + 构建）

- ✅ **形态 B：回合指令式**（非牌库）。每回合从技能栏选动作。
- ✅ **资源 = 灵气池（单池）**：不叫 MP 不叫蓝——但机制上就是灵气。总量随境界/功法涨。
- ✅ **五行不做玩家资源管理**（五行分池 = 五个蓝条，管理负担爆炸）。五行放在它该在的三层：
  1. **克制层**：技能五行 vs 目标五行 → 伤害系数（×0.5 / ×1 / ×1.5）
  2. **威力层**：所在地五行浓度 + 时辰 → 该系威力浮动（火山放火法如虎添翼）
  3. **修炼层**：区域浓度定修炼效率、灵根定亲和
- ✅ **出手层 = 12 格纯技能格**：只放技能库里的技能。**基础动作固定在场外、不计入 12 格**：平砍（器物线物理）、防御（减伤）、遁走。（"12 格不含基础动作，但基础动作始终有"）
- ✅ 战斗动作集（草案）：基础动作（平砍/防御/遁走，固定可用）+ 12 格技能 + 聚气。
- ✅ **聚气指令：要**。灵气回复为**双轨**：每回合**自动回复基础量**（随境界/功法成长）+ **聚气指令**（放弃当回合出手、额外大幅回复）——"憋大招 vs 持续输出"的节奏抉择。
- ✅ 战斗中**可用丹药/道具**（消耗灵气之外的第二个资源维度；细节数值待定）。
- 🔧 无 AI 下的战斗文字：规则引擎产出结构化战报（谁用什么招、克制、数值、特效）→ 文本层用人工模板拼装（attributes/items/forms 里的描述句是现成素材）。句子人工写，随机性来自引擎事件组合。

## 七、突破与心魔（本游戏"赌桌"与子游戏）

- ✅ **契机 = 确定性目标，非随机窗口**：**境界圆满（等级上限）+ 特定药物**。玩家永远知道"差什么"（坊市买 / 秘境找 / 宗门换）。
- ✅ **突破 = 两层混合小游戏，而非纯随机**（失败沉重 → 不能靠天命）：
  - **第一层·战前布置**：把资源（丹药×N、护脉符、功德、功法特效）**分配到各重考验**（全押一关 vs 平摊保底）——分配决定每重难度基数。
  - **第二层·逐重抉择**：**第一版 3 重考验**（灵气冲关/外魔侵扰/道基动摇…每重一个情境 2–4 选项）；结合分配资源+属性+小随机判定；累计**稳固度** → 终局映射：完美/成功/勉强/走火入魔。
  - **公式哲学：准备定难度，操作定成败，随机只留小扰动。**
- ✅ **走火入魔（失败上限）= 重伤不死可恢复**：修为倒退 + 折寿 + 心魔加重；人活着，缓过来可再战。
- ✅ **心魔 = 完整独立子系统**（同一"考验"框架的变体）：
  - 来源：业力重、杀戮多、执念深、突破失败累积心魔值。
  - 表现：突破时额外插入**心魔关**（意志抉择型，丹药难硬顶）；平时可独立爆发成遭遇事件。
  - 化解：**主要依赖道具**（静心丹/镇心符等）；🔧 扩展位：道友/师长协助化解心魔（第一版不做，仅留口子）。
- ✅ **突破药物来源三合一**：坊市购买（低阶）+ 秘境/遗迹掉落（高阶）+ 宗门贡献兑换（稀有）——花钱/冒险/混势力三条路径。
- ✅ **大境界突破引天劫**（功德低业力高 → 劫更重）——天劫 = 特殊考验序列，非纯概率。🔧 细节扩展位。

## 八、世界演化（纯 PvE）

- ✅ **共享日历**：所有 NPC/势力活在同一个时间轴，玩家闭关时世界在动。
- ✅ **势力**：宗门/家族/散修组织，各占地盘（接随机地图），有 境界/财富/关系 数值与"性格目标"（扩张/守成/复仇/寻宝…）。
- ✅ **演化节奏**：NPC 以月/季 tick 演化（按天太贵），玩家同地点/有交集时看细变化。
- ✅ **涌现事件**：势力冲突、老怪物出关、秘境开启、兽潮——由世界状态+随机流自动产生，**无预设剧本**。
- ✅ **玩家只是变量之一**：你杀的人、抢的货、救的派会改势力数值，改了才引发后续。
- ✅ **敌意存在且不分前后期**：NPC 会主动找你麻烦（见"藏匿"）；但前期世界偏被动，你的暴露程度决定被找麻烦的概率。

## 十、人物关系与势力声望（恩怨驱动，非刷分）

- ✅ **两套分开**：
  - **势力声望/好感度** = 组织对你的标签（接任务/换药/拜师/被通缉）。
  - **人物关系** = 具体的人对你的**私人账**（恩怨），独立子系统。
- ✅ **角色池**：开局生成关键人物（同期修士/坊市掌柜/宗门前辈/游方散修…），每人 = 境界 + 目标 + 性格 + 私人态度 + **有向记忆**（他记得你对他做过什么）。
- ✅ **态度由事件驱动**：救=大恩，抢=大仇，并肩=交情。**不做"送礼刷好感"**。
- ✅ **低阈值 = 行动**：恨到一定程度会设伏/告密/请人截杀；欠人情会在你濒死时出手/传艺/指路。
- 🔧 深度关系槽（师徒/道侣/本命契约）：扩展位，第一版不做。

## 十一、藏匿与怀璧（"匹夫无罪"机制化）

- ✅ **境界刻度 = 25 档**（练气一至九层 + 筑基/金丹/元婴/化神各分初期/中期/后期/大圆满；档号 1–25）。练气九层 = 开局新手区，筑基起进入四段节奏。
  - 世界观上层（炼虚/合体/大乘，即 realm_cap 12–14 原定位）为**传说存在**：玩家一世正常不可达，只作传闻/背景/绝世老怪，不铺玩家数值曲线（见第 8 条回应）。
- ✅ **双粒度**：二值门槛（理解锁/技能亮/神通亮）用**大境界**（5 档粒度）；连续对照（宝光、敌人强度、掉落匹配、寿元、灵气池）用 **25 档细刻度**。
- ✅ **品阶 ≠ 门槛刻度（废除"品阶↔档号映射表"）**：品阶（凡品~圣阶）降级为**稀有度/价值/宝光基数标签**，不参与"能不能用、多强"的核心判定。物品的强度区段由**生成模板直接定境界区段**（这件武器是练气装还是金丹装，生成时定死），机制强度只认这一套境界刻度，品阶只修饰稀有度。
- ✅ **宝光 = 分层修正公式（已定案，用户推导版）**：每件宝物的外泄贡献经过"袋压直算 → 求和 → 境界终加 → 被动终乘"四层处理：
  ```
  逐件: 贡献 = clamp( (宝光_i + 袋加算) × 袋乘算 , 下限 0 )     // 袋压是"直加+直乘"一层
  求和: 小计 = Σ 贡献_i                                          // 多件叠加（材料堆也计入，但压到 0 就白搭）
  境界: 小计' = 小计 + 境界修正(负值，境界越高压越多)            // "终加"
  被动: 外泄 = max(0, 小计' × 被动乘算(敛息术等 <1))             // "终乘"
  暴露: 外泄 > 阈值 → 分级暴露
  ```
  - 例（用户示例）：储物袋 `−5 直加 ×0.9 直乘`；低级材料(4)×20 → 每件 `(4−5)×0.9<0→0`；剑(6)→0.9；法宝(9)→3.6；灵石(9)×2→3.6×2；小计 11.7；筑基 `−10 终加` → 1.7；敛息功法 `×0.8 终乘` → **外泄 1.36** ✓（用户验算一致）
  - **设计意义：四层各归其位**——袋压（直算）= 随身容器层；境界 = 修为层；敛息类被动 = 功法层。不同资源影响不同层，修改互不干扰，也方便逐层调试。
  - 暴露分级：外泄 0 = 安全；低外泄 = 附近修士察觉；高外泄 = 强者神识扫过 → 觊觎者等级随外泄量上升
- ✅ 储物袋分档在此兑现：普通储物袋压制值低；灵阶储物戒+掩息手段压制值高。
- ✅ **公共场合暴露判定**：揣重宝进坊市/人堆停留 → 按外泄宝光检查；暴露 = 觊觎者生成（尾随/截杀/悬赏）。
- ✅ 玩家操作面：**亮宝（震慑/交易筹码）vs 藏宝（安全但吃不到红利）**、放哪个储物器、走大路还是绕野路。

## 十三、素材层分工与灵力系统定位

- ✅ MCP data（attributes/items/regions/names/scene_mod/grades…）= **内容生成器素材**：负责"东西叫什么、什么属性风味、什么背景"，引擎只消费"结构"（五行向量、品阶大档、浓度）。
- ✅ realm_cap 原意：境界 → 可正常驾驭品阶的**叙述软门槛**（生成物品的"使用要求"文案）；机制上不需要细刻度。
- ✅ **灵力系统最终定位（已拍板：混合路线 C）**：
  - **机制层：完全不纳入引擎**。引擎只消费 五行向量 + 境界刻度（25 档）+ 品阶稀有度，无阴阳时空五层体系。**强度语言 = 境界层级**（练气级/筑基级…），品阶仅稀有度/风味。
  - **素材层：保留精简版供"生成器"使用**（名字 + base + combo 三列当词缀规则，其余字段全部裁掉）。
  - **精选保留**：145 条属性里**好听/有辨识度的名字保留一小撮**（如钧雷、玄寒、星辰…）作为**特定精英敌人/Boss 的设计素材**（专属命名与机制风味），不参与常规生成。
  - **内容路线 = 混合**：核心流程/主线内容**手写精品**；掉落/秘境/杂鱼等**边缘内容程序生成**。
- ⚠️ **生成器需要大改**：从"MCP 里给 AI 看文字卡的服务器" → 改为"给引擎产结构化 JSON 的内容工厂"（详见生成器大改章节，落笔中）。
