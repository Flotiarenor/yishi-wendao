## 三、当前"探索边界"实现的是什么（**下一步要替换掉的东西**）

现状（`77bb5d6` 之后）：

- `WorldState.explored` = 走过的**格** `(cx, cy)`；写入点：`discover_here()`（落地踏勘）、
  `_set_pos_arrived(path_cells=…)`（记**整条途经路线**的格）+ 周边 `EXPLORE_RADIUS_CELLS=2` 格。
- 存档 world 键 **7 个**（`explored` 存格坐标，非位图）。
- 渲染：`tools/atlas.py` 的 `render_atlas(explored=…)` 先画完整张舆图，最后用
  **格级掩膜**（每格一个 `fill(rect)`）把踏勘过的格**替换**成实景块。
- 底图风格 `style=composed`（默认）；`/api/map/img` 的探索依据取**存档**，不吃前端参数。
- ⚠️ 语义红线：**买情报（`reveal_map_intel`）只写 `discovered`、绝不写 `explored`**
  （听说 ≠ 去过）；有回归用例 `test_fog` J7。

**实测效果与它的毛病**：同样走 5 段，踏勘格 6 → 258、受影响像素 0.01% → 0.86%。
用户实机看到的是 **白斑 + 明显格子 + 不连续**。

## 四、定案：**三层橡皮擦模型**（用户提出，我确认）—— 下一步照此实现

### 4.1 分层（自下而上）

```
底  实景层：真地形（地形色块 + 高程明暗）        ← 一直画
中  舆图层：纸底 + 单色墨（山川/路网/城镇/地名）  ← **不透明**，一直画
顶  空白层：纸色（未探明）                       ← 默认不透明，盖住下面
```

### 4.2 两把橡皮擦（**关键：不是一把**）

| 状态 | 空白层 | 舆图层 | 实景层 | 玩家看到 |
|---|---|---|---|---|
| 未探明 | **盖着** | 盖着 | 盖着 | 空白纸 |
| 听说 / 买到舆图 | **擦掉** | **盖着** | 盖着 | 舆图 |
| 亲自走过 | 擦掉 | **擦掉** | 盖着 | 实景 |

- **擦空白** = "我知道这一片了"（开局给粗舆图 / 买图）→ 依据 `WorldState.map_level`。
- **擦舆图** = "我亲自到过"（露出实景）→ 依据 `WorldState.explored` / 折线。

### 4.3 为什么这个模型对（**我原来的想法错在哪**）

1. **对比度**：我原来的推理是"舆图纸底 `#efe6cd` 与实景平原 `#8aa860` 都偏低饱和，
   混在一起都是淡色"——但那是在拿**我实现的那两层**（都是淡色、都不透明）
   去否定**用户的模型**（舆图层不透明）。用户用 Photoshop 实测：黄底黑标记 vs 全彩图，
   差别极明显。**结论：只要舆图层做成不透明，"对比度弱"这个问题根本不存在，
   我一开始就不该去调笔刷半径——那是拿错的杠杆去撬。**
2. **连续性**：用户指出的"白斑 / 格子 / 不连续"三个现象**一个根因**——
   我的擦除掩膜是**逐格画正方形**（一格 3.5px → 必然台阶；格与格没连上 → 断痕；
   "未探明"填纸色 → 在深色底上就是白斑）。

### 4.4 擦除的技术方案（**沿路径盖圆笔刷**，用户提的，我确认）

- 沿走过的**折线**按固定间距盖圆形笔刷（brush stroke），
  间距取 `半径 × 0.4` 左右——太密是浪费，太疏会出现"串珠"断痕。
- ⚠️ **半径必须按"里"定义，不能按像素**：笔刷是**世界**里的一枚圆
  （"走过去时神识所及约 X 里"）。按像素定义会让**缩放改变路的粗细**，
  看起来像换了个东西。
- 因此需要存**折线**而不只是"格"：格用于存档/统计，折线用于画。
  → `WorldState` 需新增 `trail: tuple[(x, y), …]`（世界坐标，按最小间距抽稀）。
- 圆要**柔和边缘**（`smoothstep` 衰减），硬边叠起来能看出"齿轮"。

### 4.5 已想清楚的两个实现细节（避免下次踩）

1. **抽稀必须保留端点**：折线断开会在图上留下擦不到的缝。
2. **超上限时抽稀一半，不要截断**：截断会让地图缺一段（抽稀保端点）。

## 五、下一步（照 §四 实现，建议顺序）

```
1. engine/worldmap.py：WorldState 加 trail（world 键 7 → 8），to_dict/from_dict/with_pos 同步
2. engine/game.py：_set_pos_arrived(path_points=…) 记折线（A* 的 PathResult.points），
   按 TRAIL_MIN_STEP_LI 抽稀、保端点；settings 加 TRAIL_MIN_STEP_LI / TRAIL_MAX_POINTS
3. tools/mask.py（新）：盖圆笔刷 stamp() / 沿折线 stamp_path()，半径入参用"里"
4. tools/atlas.py：改成三层——底画实景、中画舆图（**不透明**）、
   最后用两把橡皮擦把"已揭"的地方擦掉（空白层用 `map_level` 决定整张擦不擦）
5. present/mapimg.py + server/app.py：把 map_level 传进渲染（判断擦不擦空白层）
6. 测试：test_fog 补 trail 往返 / 抽稀保端点；test_map_render 补
   "未探明=纸色、已揭=舆图、走过=实景"三态判据（判据仍要**可证伪**）
7. 重记 Selenium 底图基线（地图会变，属预期）
```

⚠️ **验收要求（这次必须照做，不然又是"测试全绿、用户说没反应"）**：

- **判据要在真实链路上量**（浏览器里读 `<image>` 的 href、取回实际收到的 PNG），
  不能只在 Python 里调渲染函数；
- **判据要带量级**（像素占比/阈值），不能只判 `diff > 0`；
- **"看得见"这件事最终要用户看截图确认**——本模型读不了图，别替用户下审美结论。
